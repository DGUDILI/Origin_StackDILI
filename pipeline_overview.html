2. 실험 환경: env1 vs env2

env1 — Fixed Split

고정 Train/Test 분할 평가

원본 데이터의 레이블(ref 컬럼) 기준으로 고정 분할:

  • Train: ref ≠ "DILIrank" (다중 DB 혼합)
  • Test: ref = "DILIrank" (벤치마크, N=452)

실행 흐름

→
Step2
Encoder 학습
→

Stacking + 평가

출력 디렉토리

  • Original: DGUDILI_2026/data/, outputs/
  • Clean: DGUDILI_2026/data_clean/, outputs_clean/

장점

  • StackDILI 논문과 동일 평가 조건 → 공정 비교 가능
  • 실행 시간이 짧음
  • Encoder 학습 완료 후 즉시 결과 확인

주의

  • Train/Test 분포 이동 존재 (다중 DB vs DILIrank)
  • 단일 split → 결과 분산 측정 불가
env2 — 10-Fold CV

전체 데이터 10-Fold Stratified CV

Train + Test 전체 데이터를 합쳐 10-Fold CV로 일반화 성능 측정:

  • 전체 데이터: Original 1,850개 / Clean 1,639개
  • Encoder: env1에서 학습된 pretrained_graph_encoder.pt 재사용 (frozen)
  • Stacking: 각 fold마다 내부 5-fold OOF + LR meta 재학습

Step_CV
10-Fold CV

출력 디렉토리

  • Original: outputs_cv/results_cv.csv
  • Clean: outputs_cv_clean/results_cv.csv

장점

  • 평균 ± 표준편차 측정 → 모델 안정성 파악
  • 전체 데이터 활용 → 더 많은 fold에서 테스트
  • DILIrank 샘플도 일부 fold에서 train으로 사용 → 분포 이동 영향 완화

주의

  • Encoder가 원래 train set 기반 학습 → train 샘플이 CV test fold가 될 때 경미한 낙관 편향
  • DILIrank 샘플은 encoder 학습에 미포함 → 해당 편향 없음
  • 실행 시간이 env1보다 훨씬 김

3. DGUDILI 2026 — 모델 아키텍처

SMILES (입력) │ ├─── [ChemBERTa Branch] ────────────────────────────────────────────────────── │ ChemBERTa-77M-MLM (마지막 레이어만 unfreeze, lr=1e-4) │ → CLS 토큰 (B, 384) │ → LayerNorm(384) → Linear(384→64) → chem_feat (B, 64) │ ├─── [GraphSAGE Branch] ────────────────────────────────────────────────────── │ SMILES → RDKit mol → 43-dim 원자 특성 (원자 번호, 고리 여부 등) │ → Linear(43→64) → SAGEConv×2 (hidden=64) + BatchNorm │ → to_dense_batch → (B, 100, 64) + pad_mask [Query Q] │ → Linear(64→64) → node_q (B, 100, 64) │ └─── [MACCS Branch] ───────────────────────────────────────────────────────── SMILES → RDKit MACCSkeys → 167-bit binary vector (B, 167) → Embedding(167, 64) → maccs_kv (B, 167, 64) inactive bits → DiffAttn kv_padding_mask으로 -1e9 마스킹 [Key/Value KV] ↓ DifferentialCrossAttention (Q=node_q, K/V=maccs_kv) [arxiv 2410.05258 기반 cross-attn 변형, λ.clamp(min=1e-4)] → attn_out (B, 100, 64) → masked_mean_pool → graph_feat (B, 64) ↓ concat([chem_feat (B,64), graph_feat (B,64)]) = (B, 128) → fuse_proj Linear(128→64) → LayerNorm(64) → Linear(64→32) → GELU → Dropout(0.3) → encode_out (B, 32) ← Step3 Stacking 입력 ↓ [Stage 1: Step2] Linear(32→1) + BCEWithLogitsLoss → 이진 분류 학습 ↓ [Stage 2: Step3] Stacking: RF / ET / HistGB / XGB (5-fold OOF) → LR meta → 최종 예측

6. StackDILI — 비교 모델 파이프라인

StackDILI (논문 목표값)

env1에서의 비교 방식

Step3_stacking.py 내부에 하드코딩된 고정값으로 비교:

Step3 내 baseline 딕셔너리
AUC: 0.9736 | MCC: 0.8304 | F1: 0.9010
ACC: 0.9159 | Precision: 0.8650
Sensitivity: 0.9402 | Specificity: 0.8993
실제 StackDILI 모델을 돌리지 않음. 논문 결과값과 직접 비교.
StackDILI CV 평가

env2에서의 별도 실행

compute_stackdili_cv_baseline.py로 StackDILI를 직접 10-Fold CV:

  • GA 선택 피처 (Feature/Feature.csv) 기준
  • 사전 학습된 base model 파일 (Code/Model/best_model_*.pkl) 로드
  • 각 fold에서 base models + stacking meta 재학습
  • 출력: outputs_cv[_clean]/stackdili_baseline.json
Code/Model/ 디렉토리 (pkl 파일들)이 없으면 실행 불가. StackDILI 원본 코드에서 학습된 모델 파일 필요.

StackDILI 파이프라인 구조 (개념)

단계내용InputOutput
피처 선택 Genetic Algorithm으로 FP 피처 선택 Dataset_feature.csv (전체 ~425 dim FP) Feature/Feature.csv (GA 선택 피처 subset)
Base 학습 RF / ET / HistGB / XGB 각각 학습 GA 선택 FP (N_train, GA_dim) Code/Model/best_model_*.pkl
Stacking 5-fold OOF → LR meta classifier OOF 예측 확률 (N_train, 4) Code/Model/best_model_stacking.pkl

StackDILI는 딥러닝 없음. 순수 FP + GA 피처 선택 + Stacking 앙상블. DGUDILI_2026은 딥러닝 Encoder로 32-dim 표현을 학습한 뒤 동일한 Stacking 구조를 사용.

9. env2에서 env1 Encoder 재사용 — 편향 분석

왜 편향이 생기는가

env2 CV는 전체 데이터(train + test)를 10-fold로 나누지만, encoder는 이미 non-DILIrank 샘플(원래 train)을 학습에 사용한 상태입니다. 그 샘플들이 CV의 test fold로 들어올 때 encoder가 이미 "본" 데이터를 평가하게 됩니다.

env1 encoder 학습 → train_graphs.pt (non-DILIrank 1,398개) 로 BCELoss 최적화 env2 CV → 전체 1,850개 (train 1,398 + test 452)를 10-fold 분할 → encoder는 이미 1,398개를 "본" 상태로 feature 추출 → 해당 샘플이 test fold가 될 때 → 낙관적 평가 편향

샘플별 편향 여부

샘플 종류encoder 학습 포함env2 test fold 시영향
non-DILIrank (1,398개) 포함됨 낙관적 편향 있음 encoder가 해당 샘플 이미 학습 → feature가 과도하게 discriminative할 수 있음
DILIrank (452개) 미포함 편향 없음, 공정한 평가 encoder 학습에 전혀 사용되지 않음 → 독립적 평가

왜 Nested CV(이상적 방법)를 쓰지 않는가

편향을 완전히 제거하려면 각 fold마다 encoder를 처음부터 재학습하는 Nested CV가 필요합니다.

Nested CV (이상적)

10 outer folds × encoder 재학습 = 10 × 200 epochs × GraphMACCSEncoder = 실험 불가 수준의 계산 비용

완전히 공정하지만 현실적으로 실행 불가.

현재 방식 (실용적 타협)

env1 encoder 1회 학습 (frozen) + env2 에서 stacking만 fold별 재학습 = 빠르고 합리적인 근사

편향이 제한적인 이유:

  • encoder frozen → stacking만 재학습
  • val_AUC early stopping으로 train set 과적합 억제
  • encoder 파라미터 수가 상대적으로 작음 (~수백만)

env2 결과 해석 방법

평가 목적신뢰도근거
DILIrank 샘플에 대한 일반화 높음 encoder 학습에 미포함 → 완전히 독립적
non-DILIrank 샘플에 대한 일반화 주의 필요 encoder가 이미 해당 샘플 학습 → 경미한 낙관 편향
Stacking 레이어 안정성 (분산) 유효 fold별 stacking 재학습 → 평균±표준편차 의미 있음
StackDILI와 공정 비교 env1 사용 권장 env2 수치는 편향으로 인해 과대평가 가능성
논문 작성 시 권장: 주요 성능은 env1 (DILIrank fixed split) 기준으로 보고하고, env2는 "모델 안정성 확인" 용도로 보조 기재. env2 수치 인용 시 encoder 재사용 편향이 있음을 명시.
